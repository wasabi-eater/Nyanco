# 型システムと0.9への移行

文法の変更は不要です。関数定義、quotation、リストを実行する記法、演算子、不足項、`;`、`->` はそのまま使えます。ただし、以前実行できたプログラムのうち、型やスタック形状が実行時の条件で変わるものは拒否します。

## 値の型とスタック効果

値の型は `num`（倍精度数値）、`bool`、`string`、同じ型の要素からなるリスト `[a]`、quotationです。`int` は `num` の別名で、整数専用型ではありません。`a` は任意の値の型を表します。

関数には入力・出力のスタック効果を推論します。

```text
square : 'a mul => ..s 'a -- ..s 'a
dup    : ..s a -- ..s a a
drop   : ..s a -- ..s
```

`..s` は下側にある任意のスタック列です。左右で同じ名前なら、その型と並びは維持されます。`∅` は空スタックです。`a`、`a1` などは異なる型変数を表し、同じ名前の出現は同じ型です。

quotationの表示は `{ 入力 -- 出力 }` です。

```haskell
n makeAdder = {_ + n}
```

```text
makeAdder : 'a add => ..s 'a -- ..s { ..s1 'a -- ..s1 'a }
```

この関数はAddのinstanceを持つ型の値を受け取り、同じ型の値を加算するquotationを返します。`..s` と `..s1` は別々のスタック下部です。

## 節単位のスタック参照

`_n`・`$n` は `;` で区切られた節の開始時に束縛します。推論器は最大の参照番号までスタック行を分解し、各番号の値型を保存します。`_n` の位置を除いて行を再構築し、`$n` の位置は保持します。同じ番号の参照は同じ型変数を共有するため、`_ + _` は1入力、`_1 + _` は2入力になります。`_`・`$` はそれぞれ番号0の略で、同一節で同じ番号の両形式を混在させると構文エラーです。

`()`・`[]`・record内の参照も同じ節で扱い、quotationでは独立した節を開始します。括弧内の `;` はその位置の評価スタックで新しい節を開始し、その束縛は閉じ括弧の後にも有効です。省略された二項演算子の項は明示的な参照の束縛後に、残りのスタック行から推論します。Go変換でも同じ束縛順序を使い、参照をGoの既存ローカル変数へ割り当てるため、実行時の評価スタックは不要です。

連鎖比較では隣り合う各項の型を比較演算子の型と単一化し、全体はboolになります。実行時に短絡される後続の項も検査します。短絡され得る項の内部の `;` で新たに束縛したスタック参照は、連鎖の外では利用できません。

## 型を見る

```powershell
node cli.mjs --types examples/typed.hst
node cli.mjs --type "dup"
node cli.mjs --check examples/typed.hst
```

REPLでは `:type dup`、`:type square` などを使います。式の型表示は、必要な入力を含む一般的なスタック効果を推論するため、現在スタックが空でも `:type (+)` と入力できます。実行する `(+ )` は値が2個必要なので、空スタックなら型エラーです。

型表示・型検査はプログラムを実行しません。`--eval` と通常のファイル実行でも、プログラムを実行する前に検査します。未使用の関数や、実行されない分岐のquotationも検査対象です。

## 多相性と推論

```haskell
x identity = x
main = 3 identity print True identity print
```

`identity` は `..s a -- ..s a` となり、呼び出すたびに型変数を具体化します。数値と真偽値で同じ関数を使っても構いません。

`{dup} -> copy;` のような新しい変数への束縛も、周囲の型変数に依存しない部分を一般化します。残りのスタックや捕捉変数と共有する型変数は、勝手に一般化しません。

通常の再帰・相互再帰と、再帰するquotationに対応します。再帰の中でスタックの下側に保持する値の数が異なる場合も、その下部が同じ型の列として維持される限り推論できます。再帰呼び出しごとに値の型を変える多相再帰は対象外です。

## 型注釈

注釈は任意ですが、書いた場合は検査されます。

```haskell
square : num -> num
x square = x * x

identity : a -> a
x identity = x

add : (num num) -> num
add = (+)

inc : () -> {num -> num}
inc = {+ 1}
```

矢印の左が取り出す型、右が積む型です。複数の型を並べられ、`()` は0個です。`[num]` などのリスト型や、`{num -> num}` のquotation型も書けます。型変数は小文字で始めます。

入力と出力の下部に共通のスタック列が暗黙に補われます。表示用の `..s` / `--` は注釈には書けません。高階関数の複雑なスタック列の共有関係を注釈に明示する構文はまだなく、その場合は注釈を省略して推論させます。

`a -> a` と宣言した関数は、任意の型で動く必要があります。実装が `(+ 1)` なら数値しか扱えないため、型エラーです。一方、多相な `identity` を `num -> num` に制限する注釈は許されます。

## リストと分岐

リストは同じ型の値を収めます。リスト内部を空スタックで実行する仕様は維持しています。

```text
[1 + 2; 4 dup]       -- [num]
[[1] [2 3]]        -- [[num]]
[1 True]           -- 型エラー
```

`if` の両分岐には、同じ入力・出力スタック効果が必要です。

```text
True {1} {2} if       -- 有効
True {1} {"two"} if   -- 型エラー
```

例のFizzBuzzは、数値の分岐を `n show` にして、常に `string` を返すよう変更しました。`show` は値を表示用の文字列へ変換します。

## 共有スタックと反復

quotationは引き続き呼び出し元のスタックを共有します。反復には次の型制約を課します。`S` は追加の累積状態を含むスタック列です。

| 関数 | quotationの効果 |
|---|---|
| `each` | `S a -- S` |
| `map` | `S a -- S b`（先頭の `b` を結果リストへ収める） |
| `filter` | `S a -- S bool`（先頭の真偽値を取り出す） |
| `fold` | `S b a -- S b`（`b` は累積値） |
| `when` | `S -- S` |
| `while` の判定 | `S -- T bool` |
| `while` の処理 | `T -- S` |

値の内容は更新できますが、反復ごとにスタックを増やしたり型を変えたりすることはできません。

```text
0 [1 2 3] {+} each            -- 有効、6
0 [1 2 3] {+; dup} map        -- 有効、[6 [1 3 6]]
0 {dup; < 3} {+ 1} while      -- 有効、3
[1 2] {dup} each              -- 型エラー、スタックが増え続ける
True {1} when                -- 型エラー、Trueの場合だけ1値増える
```

空リストでも、一定の条件でも、型の制約は省略しません。値によってスタック長が変わることを許す依存型や可変長タプルは未実装です。

## 変数とREPL

変数は `->` で宣言し、既定でimmutableです。`3 -> mut x; x := x + 1` は有効ですが、`x := True` は型を変えるため拒否します。`mut x = 3` は構文エラーです。同じスコープでの再宣言は拒否し、内側の新しい宣言によるシャドーイングは異なる型でも許可します。

mutable変数の型変数は一般化しません。参照するたびに同じ単相型を使い、再代入の右辺と単一化します。mutable変数に由来する型変数は、それを捕捉したimmutableなquotationや関数の一般化からも除外します。これにより多相な参照を経由して異なる型を書き込むことを防ぎます。

`[] -> mut xs` のように未確定の型も許可します。REPLでは型の制約をセルに保持し、`xs := [1]; xs := []` の後も要素型はnumのままです。推論時には保存型を複製し、検査・実行が成功した場合だけ制約を保存します。`:type` や失敗した入力で型が固定されることはありません。グローバル変数と関数の名前の衝突も拒否します。

`=` はローカルでも関数定義です。本文の入力行と出力行を推論して、名前の参照時にその効果を適用します。再帰的なローカル関数は効果の候補を求め、共有するスタックの末尾だけを多相化して再検査します。環境に含まれる型変数は一般化から除外するため、捕捉したmutable変数の型は維持されます。変数に格納したquotationの参照は1値の生成であり、関数呼び出しとは区別します。

REPLでは各入力を実行前に検査します。定義の変更や`:load`でも、既存の定義・グローバル変数との整合性を検査します。失敗した定義更新は反映せず、失敗した式の変数更新は戻します。実行時エラーが起きる前の出力は戻せませんが、型エラーならその行の出力も一切実行されません。

## 保証の範囲と実装

ガード付き定義とcaseはパターンと条件を持つ節として上から処理します。パターンの引数型を環境へ登録した後、残ったスタック行を条件の入力にします。条件の出力行からboolを1つ取り除き、残りを本体の入力にします。条件は値を消費・生成できます。条件が偽なら次の節には元の入力スタックを渡します。ガードの依存関数も再帰グループの解析に含めます。網羅性は検査しません。

caseの分岐ごとのパターン数は同じである必要がありません。同一の入力行に各パターンの制約を適用し、全分岐の最終出力行を単一化します。通常の `->` もトップレベルのパターン数だけ行から取り除き、コンストラクタやリストのフィールド型を分解して各変数に割り当てます。immutableな束縛は従来どおり一般化し、`mut` の付いた変数は単相のまま保持します。

型注釈の区切りは `:` です。`::` は `Push` と同じ `..s [a] a -- ..s [a]` の演算子です。空・固定長リストパターンでは引数型を `[a]` と単一化し、各要素を `a` と照合します。`prefix :: last` または `prefix last Push` パターンでは末尾以外を `[a]`、末尾を `a` と照合します。パターンマッチはリストの長さを実行時に検査します。

ADTは型名と型引数からなる名目的な型として扱います。`num option` と `num other` はフィールド構造が同じでも単一化できません。同じ型名同士では型引数を再帰的に単一化します。コンストラクタの型は宣言から生成して一般化し、呼び出すたびに型変数を具体化します。例えば `Some` は `..s 'a -- ..s ('a option)` です。

コンストラクタパターンでは引数をコンストラクタの結果型と単一化し、各フィールドの型を内側のパターンへ伝えます。`(x Some)` の `x` はoptionの型引数と同じ型になります。ワイルドカードでもフィールドの型制約は維持します。通常の関数と同様に全節の入力・出力を照合し、再帰関数にも既存の推論アルゴリズムを適用します。

実行済みのADT値から型を復元するときも宣言と各フィールドを照合します。mutable変数では型引数の未確定変数を一般化せず、REPL入力をまたいで制約を保持します。ADT内にquotationがある場合は、その中の関数依存関係も再定義時に検査します。

型推論は値とスタック列の型変数、単一化、occurs check、一般化・具体化からなります。関数の依存グラフを強連結成分に分け、再帰グループの効果の候補を求めた後、値型を共有しながら共通のスタック下部を多相化して、全本体を再検査します。型注釈の全称変数は固定して検証し、実装が注釈より狭い型しか受け付けない場合を拒否します。

正格評価のインタプリタとGo変換バックエンドがあります。Go変換でも同じ型推論・検査を実行し、型エラーがあれば生成を中止します。コンパイル時のスタック行型から関数とquotationの入出力数を解決し、Goの引数・複数戻り値・ローカル変数へ変換します。実行時の評価スタックは生成しません。高階関数やquotationは呼び出しの型に合わせて特殊化します。変更されないスタックの接頭部は呼び出し側に保持し、quotationを引数に渡す場合もその接頭部を切り離して型を解析します。値の表現自体はGoの `any` で、具体型への最適化は未実装です。GADT、値型の多相再帰、依存型、任意階数の多相型注釈は未実装です。

ゼロ除算、空リストの `head`、数値の範囲、パターンの網羅性、停止性などは値に依存するため、実行時の検査が残ります。型検査が通っても、これらの実行時エラーやステップ上限による停止はあり得ます。

通常の公開APIは `compile` と `VM.evaluate` で静的検査します。実行器単体の回帰テストだけは `checkTypes: false` を指定して、意図的に不正な値を渡した場合の防御的な実行時検査も維持しています。CLIに検査を無効化するオプションはありません。

型変数には `'a`、型適用には `'a option` という後置記法を使用します。`data 'a option = None | 'a Some` からコンストラクタ型を生成します。複数の引数は `'e 'a result` のように並べます。旧構文は互換用に受け付けます。

関数呼び出しを含む隣接コマンド列は二項演算子より優先されます。`x f + a` では `x f` 全体を0消費1生産のオペランドとして検査します。`[n n + 1]` は左辺が2値になるため拒否し、`[n; n + 1]` と区切ります。型検査は実行前に行い、式の各辺は独立した空スタックで評価します。


## Record rows (0.22)

recordは構造的に型付けします。`{x: num, y: bool}` は閉じたrecord、`{x: num | 'r}` は `x` 以外のフィールドをrow変数 `'r` で表すrecordです。`{:}` は空record型、`{| 'r}` はフィールドを要求しないrecord型です。スタックの残りを表す `..s` とrecord rowは別のkindです。

`.field` はrecordから該当フィールドを取り出す1消費1生産の処理です。推論では入力を `{field: 'a | 'r}` と単一化し、`'a` を出力します。同じ入力への複数のフィールドアクセスは必要フィールドを統合します。例えば `r sum = r.x + r.y` は `{x: 'a, y: 'a | 'r}` と `'a add` 制約を要求します。

record rowの単一化では共通ラベルの型を単一化し、片方にだけ存在するラベルをもう片方のrow変数に渡します。両側に未一致のフィールドがある場合は新しい共有tailを導入します。閉じたrowへ不足フィールドを追加することはできません。row変数には既出ラベルを再び含めない制約（lacks constraint）を保持し、通常のoccurs checkも行います。汎化・インスタンス化では値型・スタックrowと同様にrecord row変数も扱います。

record値のフィールド式はそれぞれ0消費1生産です。`.field` は取り出したquotationを自動実行しません。可変変数では他の型と同様に単相性を維持し、再代入によるフィールド構成・型の変更は拒否します。Go生成ではrecordをフィールドmapとして表し、アクセス結果をGoの局所変数に格納するため、実行時の評価スタックは導入しません。


## 括弧を跨ぐ節（0.23）

リストとrecordの評価時にも、明示的な参照の束縛表を外側と共有します。値を集めるローカルスタックと節の参照の束縛表は別のものです。型推論とGo生成でも同じ束縛表を共有します。recordの空フィールド `{x:}` は不足項として推論し、record評価前に対応する値型を外側のスタック行から取り出します。quotationは従来どおり呼び出し時に独立した節を開始します。


## 型クラス制約（0.24）

`class 'a describe where` のメソッド `describe : 'a -> string` には暗黙に `'a describe` 制約を付与します。型変数は必要なクラスの集合を保持します。単一化する2つの型変数では集合を統合し、具象型との単一化では対応するinstanceの存在を検査します。汎化・インスタンス化はこの集合も保持するため、通常のHM推論に沿って関数、リスト要素、recordのフィールド、quotationへ制約が伝わります。

明示的な注釈 `'a describe => 'a -> string` を検証するときは、注釈の変数をrigid化し、必要な制約が宣言されていることも確認します。instanceの本体はクラス型引数をinstance対象型で置換したメソッド型に対して検査します。重複instanceと未実装メソッドは宣言時に拒否します。標準演算子も型クラスを使います。

入力で判別できる単一パラメータのクラスに対応します。メソッドの型にはクラス型引数を直接型に持つ入力が必要です。0.31では条件付きinstance、パラメータ付きADT・リストへのinstanceにも対応しました。出力型だけで選択するメソッドとスーパークラスは未対応です。

インタプリタは該当入力の型タグで検査済みinstanceを選びます。Go生成では呼び出し箇所の型に合わせてinstanceの実装を直接呼び出します。quotationも既存の特殊化機構を使い、評価スタックや型クラス辞書をGo実行時に追加しません。


## 演算子の型クラス（0.25）

標準演算子のスキームには、最初からクラスの制約付きメソッド型を使います。例えば `add` の `+` は `'a add => 'a 'a -> 'a` です。単一化時には明示的instanceに加えて、元から存在する基本型向けの演算を利用できるか検査します。従来の全値型向け等値比較を維持する `eq` だけは普遍的に利用可能であり、独自instanceがない場合は型変数に未解決の制約を残しません。独自instanceがある場合はその前提条件の検査に必要な制約を保持します。

二項演算子・連鎖比較の型検査は、このメソッドのスキームを適用します。0消費1生産のオペランド制約、不足項の束縛、左右の型の一致は維持します。インタプリタは評価済みのオペランドの型でinstanceを選択します。Go生成は推論済みの演算子の入出力型を保持し、ADT向けの演算はinstanceの特殊化した関数を直接呼び出します。基本型向けの演算は従来の実装を使用します。

0.26から標準の `add` などは常に有効です。REPLの空の環境でも `:type +` は `'a add => ..s 'a 'a -- ..s 'a` になり、`f = +` はこの制約を汎化して保持します。数値リテラルや明示的なnum注釈と単一化すると、既存のnum演算で制約が解決されます。演算子の所属クラスは1つであり、重複したクラス宣言、基本型向けinstanceの上書き、メソッドの不足、不正な入出力型は拒否します。0.31では型引数付きADTへのinstanceにも対応しています。


## 範囲演算子（0.27）

`..` と `..=` は `num num -> range` の組み込み二項演算子です。型クラスによるオーバーロードは追加していません。端点が安全な整数であることと両端の差の上限は、既存の `range` と同様に実行時に検査します。省略項を含むオペランドの推論は他の二項演算子と共通です。


## 隣接する二項演算子（0.28）

隣接する演算子の間には不足項を挿入し、通常の優先順位で構文木を作ります。`+ *` は「不足項 + (不足項 * 不足項)」です。型推論と実行時の不足項束縛は既存の処理を使い、明示的な `_`・`$` の束縛を先に行います。例えば `f = + *` は `'a add, 'a mul => ..s 'a 'a 'a -- ..s 'a` と推論されます。連鎖比較も従来の短絡評価を維持します。


## Push（0.29）

リストの末尾追加 `Push` とその糖衣構文 `::` は `['a] 'a -> ['a]` と推論します。`::` は式・パターンとも左結合です。両方のパターン記法を同じ分解ノードに変換し、第1パターンにリスト型、第2パターンに要素型を単一化します。空リストへの一致判定は実行時に失敗します。Go生成でもリストをコピーして追加・分解し、評価スタックは導入しません。


## タプル（0.30）

`#(num string [num])` は位置ごとに異なる要素型を持つタプル型です。閉じたタプル同士の単一化では要素数と各位置の型を検査します。`.n` は入力に少なくともn+1個の要素を要求し、n番目の型を出力します。追加の要素は独立したtuple-row kindの変数で表し、`#('a | 't)` のように表示します。既知の共通prefixを単一化し、長い側の残りを短い側のtailと単一化します。値型・スタックrow・record rowとはkindを分けています。

タプルリテラルの内部は空の評価スタックで推論し、残った型の列を閉じたタプル型にします。参照の束縛表は外側と共有します。タプルパターンは各位置を個別に型付けし、要素数を固定します。型注釈にトップレベルの `->` がなければ、単一の出力型を指定する省略形として扱います。例えば `a : #(num string)` は `a : -> #(num string)` と同義です。

インタプリタ・Goともリストと区別するタプル値を持ち、位置によるアクセスを行います。Goには引き続き評価スタックを生成しません。


## ジェネリックinstance・each・range（0.31）

instanceのheadは通常の型構文で解析します。メソッド型のクラス変数をheadで置換し、headの型変数を新しい名前へ置換してから実装を検査します。呼び出し時はheadを新しくインスタンス化して実引数型と単一化し、`=>` の前提制約を検査します。型変数の名前がメソッド固有の変数と衝突しないようにしています。重複判定と実行時dispatchは外側の型コンストラクタ単位です。同じクラス・同じ外側の型について、型引数だけが異なるinstanceの共存は未対応です。

`each` はコンテナ型と要素型の関係を型変数の制約として保持します。汎化・インスタンス化で両者を一緒に複製し、リスト・range・独自instanceへ具体化した時点で要素型を単一化します。quotationの入出力に同じスタックrowを要求するため、累積値は更新できてもスタック形状は変化しません。Go生成でも、コールバックが書き換える累積値を「型が等しいので未変更」と誤認しないよう、必要な引数と戻り値を残します。

`range` は端点と包含フラグを持つ値型です。`..`・`..=` はリストを確保せず、`each` が数値を順に渡します。Goでも専用の値とループに変換します。型表示とサンプルは `num`・`bool`・`string`・`range`、`add` などの小文字始まりを標準にし、旧表記は互換エイリアスとして正規化します。


## 代数的エフェクト（0.32）

操作の宣言は入出力型の組で、0.34から明示的な型引数を持てます。通常の関数としてスタック効果を適用し、ハンドラがあるかどうかは実行時に判定します。0.35からエフェクト行を推論し、明示的な行への適合も検査します。エントリポイントの未処理操作を一律に禁止する規則はありません。

`handle` のbodyは空スタックから結果列を生成します。0.36から個数は任意です。ハンドラrecordの各フィールドには、対応する操作の入力と継続を受け取り同じ結果列を返すquotationを要求します。継続には操作の出力を入力、結果列全体を出力とする専用型を与え、`call` のquotation型とは区別します。`h a handles` 制約は未知のハンドラ型と結果型を結び、汎化・インスタンス化を経ても保持します。recordへ具体化した際にフィールドごとの操作名と型を検査します。

`->` で束縛した値の型を汎化するときには、その節に入ってきたスタックの自由型変数も除外します。例えばハンドラ入力の継続kを独立した多相値にしてしまうと、宣言された再開型と実際の `k resume` の入力型が切り離されるためです。

インタープリタはgeneratorで現在の実行位置を保持し、Goは中断したgoroutineの呼び出しフレームを保持します。どちらも再実行による継続の模倣はしません。単発継続の使用済み・有効期間は動的に検査します。ハンドラが再開せずに戻る場合やエラーの場合には、停止中の計算を終了させます。


## 戻りスタックのbottom（0.33）

`!` を値型ではなく戻りスタックのbottomとして表します。操作と関数の `input -> !` は、正常な出力経路を持ちません。型推論ではbottom経路を他の戻りスタックへ適合させ、分岐の正常な戻り経路だけを単一化します。全経路がbottomなら全体もbottomです。正常に戻らない呼び出しの後は、その節の残りを推論しません。

分岐の結果をまだ集約している型変数には、bottomを暫定的な結果として保持します。後から正常な戻り経路が見つかればそちらの型へ統合します。一方、確定した非復帰呼び出しの結果は固定bottomとして返すため、ハンドラが結果型を指定しても中断点の到達不能性は失われません。

明示的な `!` は一方向の約束として検査します。戻り値を持つ関数・quotationを非復帰型として扱うことはできません。非復帰effectの継続は入力自体をbottomとし、`resume` の入力とは単一化できないようにします。実行時にも再開を拒否します。

Go生成では非復帰経路の後続を生成せず、正常な分岐の戻り値だけを渡します。非復帰関数・quotationが消費しない入力側の共通部分も型に保持し、呼び出し元の値を不要な引数へ展開しません。これは高階関数の特殊化が非復帰経路で増え続けるのを防ぐためにも必要です。


## 後置制約と多相effect（0.34）

型クラス制約は `'a add` の形で解析・表示します。内部のクラス名と型引数の対応は維持し、旧前置構文も入力時に正規化します。instanceのheadは `instance ('a box) add where`、前提制約付きなら `instance 'a add => ('a box) add where` となります。

`effect 'a yield : 'a ->` の型引数は宣言内で束縛し、操作を呼ぶたびに新しくインスタンス化します。ハンドラの検査では操作の型引数を新しいrigid型に置換して、すべての型に対して実装できるかを検査します。操作パラメータがハンドラの結果型や外側の単相変数へ流出する場合は拒否します。quotationのキャプチャした自由型変数も保持し、関数から返されたハンドラや型注釈を経たハンドラでも、mutableな状態の型を勝手に汎化しません。

Go生成では操作の値を既存の引数・戻り値の受け渡し機構で運びます。型引数の数や具体型によらず、宣言された操作の入力・出力個数は一定です。再開する値の型の対応と、非復帰effectの再開禁止も維持します。


## エフェクト行の推論（0.35）

quotationと継続には、入出力スタックとは別にeffect-row kindの情報を持たせます。各要素は操作名と宣言順の型引数で、値型と同じ型変数を参照します。例えばaskの戻り値をyieldへ渡すと、`'a ask`と`'a yield`の引数は同じ変数になります。汎化・インスタンス化でもこの対応を保存します。

推論中は操作集合の和、未知の行、handlerによる操作名の除外を依存グラフとして保持します。blockの本体は独立した収集先で推論し、実行用の組み合わせ関数が持つ型の関係を通じて、実行時の行へ伝播させます。分岐は可能な操作を合併するため、実際には選ばれない分岐や空リストのコールバックも保守的に含まれます。再帰の候補を検査する際は同じスタック規則の下で操作集合も集約します。

handlerは既知のフィールド集合をbodyの操作集合から除きます。handler自身の操作は外側で実行されるため除外しません。操作の普遍的なhandler型検査と、呼び出し箇所の型引数でhandlerの外向き操作を具体化する処理を分けています。継続の再開は処理済み操作を除いた計算の行を引き継ぎます。

閉じた注釈は許可する操作と型引数の上限です。`/ {}`には未知の行も適合しません。`/ { | 'e}`は行変数を明示し、高階関数の引数と結果の行の対応を記述できます。省略された行は未確定として推論します。mutableなquotationをキャプチャする場合には行の共有を保存し、後から代入されたquotationの操作が別名の関数から漏れても検出します。

この行は宣言された代数的エフェクトを追跡するもので、print・代入などの全副作用を分類する体系ではありません。また、一般の行の差集合を表す記法は公開していません。未知のhandlerへの適用関係は内部に保持し、具体的なrecordを渡した時点で解決します。Go生成では行のための評価スタックや実行時辞書は追加しません。


## handleの結果スタック（0.36）

handlerのanswerは単一の値型ではなくスタックrowです。bodyと各handlerの出力rowを単一化し、`resume`は自身の未消費prefixにanswer rowを連結します。`handle`も外側のprefixに同じanswer rowを連結します。未確定の結果列は内部のconcat-rowで保持し、呼び出し時の具体化で通常のpush列へ展開します。型表示の `..s ++ ..s1` はこのスタック列の連結を表します。

インタープリタでは結果列をまとめて受け渡します。Go生成では関数の直接の複数戻り値を、エフェクト境界のメッセージに詰め、呼び出し側で静的に分かる個数のローカル値へ展開します。実行時の評価スタックを導入するものではありません。単発継続・deep handler・エフェクト行の差し引きは維持します。


## ユーザー定義の関連型（0.37）

classは関連型名の順序付きリストを保持します。メソッド型内の関連型名を衝突しない内部型変数へ置換し、対象型とこれらの変数を結ぶクラス制約を付けます。対象型の型変数にはクラスごとの関連型の列を保存し、同じ対象型の制約を再度要求すると各関連型も単一化します。この情報を自由変数の列挙、汎化、rigid化、再インスタンス化、Go生成用の環境複製に含めます。

対象が具体化したら既存のinstance選択を行い、headと実引数を単一化した置換で関連型の定義を具体化し、要求された関連型の列と単一化します。その後、instanceの前提制約を再帰的に解決します。関連型は対象の型によって決まり、独立したdispatchキーを追加しません。

instanceの前提制約を可変長の型変数列として保存するようにし、通常のクラス、ユーザー定義の関連型、組み込みeachのコンテナ・要素関係を同じ入口で検査します。instanceのメソッド型はheadと関連型定義を代入した型で検査するため、宣言した関連型と実装の戻り型が異なれば拒否します。

同一の対象型に対する複数の制約は関連型を共有します。例えば `'c 'a unpack, 'c 'b unpack` は `'a`と`'b`を等しくします。推論した制約は関数、quotation、record、mutableな値を経ても保持し、Go側のdispatchも同じinstanceを選択します。
